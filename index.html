About

Can AI agents discover and validate new model architectures?

Each task gives an agent a research problem, code, data, a cluster, and a scheduler. The agent maintains competing hypotheses and assigns each available worker to the highest-value experiment it can run. It submits one model for evaluation on unseen data or harder conditions.

Release 1.0

Initial task suite

Two large-scale language-model tasks and a 50-task CPU suite. In each one, the agent controls both the research plan and the compute budget.

01 Matrix residuals · GPU

HillClimbBench-RMT

Residual Matrix Transformers replace the usual vector-valued residual stream with a matrix-valued memory, expanding state capacity while keeping parameter count and computation nearly fixed. The agent has four H200 GPUs for ten hours to develop a new RMT architecture, including changes to kernels and training. The final model is tested on a separate OpenWebText split.

02 Recurrent depth · GPU

HillClimbBench-Loop

Depth-recurrent Transformers reuse a shared block across multiple iterations, increasing computation while sharing parameters across depth. The agent searches for a new state, transition, routing, or topology that makes additional iterations useful and stable. Candidates stay below 350M unique parameters and train at fixed token budgets; final evaluation applies the shared block eight times.

03 50 paper-derived tasks · CPU

HillClimbBench-CPU

Can an agent take an architectural idea from a research paper and iterate on it under a limited compute budget? HillClimbBench-CPU contains 50 such problems spanning recurrent memory, equivariance, operator learning, attention, state-space models, and other model families. The agent receives a paper summary, reference implementation, one CPU thread, and a harder final test. It proposes, implements, and tests an architectural change. The selected model and reference are retrained across five seeds.
